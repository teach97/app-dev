## 1. 자동 문서화의 원리

### 1-1. OpenAPI

FastAPI는 코드를 읽어 **OpenAPI 문서** 를 자동으로 만듭니다. 서버를 켜고 아래 주소를 열면 원본을 볼 수 있습니다.

```
http://127.0.0.1:8000/openapi.json
```

이 JSON 한 덩어리가 **API의 설계도** 입니다. 경로, 메서드, 파라미터, 요청·응답 형식, 상태 코드가 전부 들어 있습니다.

**지금까지 이걸 직접 작성한 적이 없다는 점이 중요합니다.** 타입 힌트와 Pydantic 모델에서 자동으로 생성된 것입니다.

|용어|의미|
|---|---|
|**OpenAPI**|API의 구조를 기술하는 **국제 표준 규격**. 예전 이름은 Swagger Specification|
|**`openapi.json`**|그 규격에 맞춰 FastAPI가 자동 생성한 **실제 문서 파일**|
|**스키마 (schema)**|데이터의 구조 정의. Pydantic 모델이 여기로 변환됨|

### 1-2. 세 가지 화면

**같은 OpenAPI 문서** 를 서로 다른 방식으로 보여줍니다.

|주소|이름|특징|
|---|---|---|
|`/docs`|**Swagger UI**|직접 실행 가능. 개발·테스트용|
|`/redoc`|**ReDoc**|읽기 전용. 설명이 넓게 표시되어 공유용|
|`/openapi.json`|**원본**|다른 도구가 읽어 가는 형식|

`/redoc`은 지금까지 안 써 봤을 것입니다. **지금 한 번 열어 두 화면을 비교해 보세요.**

### 1-3. 왜 문서를 다듬는가

자동 생성만으로는 부족합니다. 지금 `/docs`를 열면 이런 상태입니다.

- 엔드포인트 20여 개가 **그룹 없이 한 줄로 나열됨**
- 각 항목에 **함수 이름을 변형한 제목** 만 표시됨 (`Search External Books`)
- 각 필드가 **무엇을 뜻하는지 설명이 없음**
- **어떤 오류가 날 수 있는지** 알 수 없음

이 상태로는 다른 사람에게 넘길 수 없습니다. 오늘 이걸 고칩니다.

## 2. 문서를 다듬는 도구

오늘 쓸 도구를 먼저 한눈에 봅니다.

|도구|붙이는 위치|효과|
|---|---|---|
|`title`, `description`, `version`|`FastAPI()` 생성 시|문서 상단 제목·설명|
|`openapi_tags`|`FastAPI()` 생성 시|태그 그룹의 설명과 순서|
|`tags`|엔드포인트 데코레이터|엔드포인트를 그룹으로 묶음|
|`summary`|엔드포인트 데코레이터|목록에 보이는 한 줄 제목|
|**독스트링**|함수 첫 줄 `"""..."""`|펼쳤을 때 나오는 상세 설명 (마크다운)|
|`response_description`|엔드포인트 데코레이터|성공 응답 설명|
|`responses`|엔드포인트 데코레이터|**발생 가능한 오류** 를 문서에 표시|
|`Field(description=, examples=)`|모델 필드|필드 설명과 예시값|
|`model_config`|모델 클래스|`Try it out`에 미리 채워질 전체 예시|

### 2-1. 앱 전체 정보

```python
app = FastAPI(
    title="도서 관리 API",
    description="도서를 등록·조회하고 외부 검색으로 정보를 가져오는 API",
    version="1.0.0",
    contact={"name": "홍길동", "email": "hong@example.com"},
)
```

### 2-2. 태그로 그룹 나누기

엔드포인트에 `tags`를 붙이면 문서에서 묶여 표시됩니다.

```python
@app.get("/books", tags=["도서"])
```

태그 **자체에 설명** 을 붙이려면 앱 생성 시 목록을 넘깁니다.

```python
tags_metadata = [
    {"name": "도서", "description": "도서 등록, 조회, 검색"},
    {"name": "외부 연동", "description": "Google Books와 날씨 API 연동"},
    {"name": "시스템", "description": "서버 상태 확인"},
]

app = FastAPI(openapi_tags=tags_metadata, ...)
```

> **참고:** 문서에 표시되는 **순서** 는 이 목록의 순서를 따릅니다. 알파벳순이 아닙니다.

### 2-3. 엔드포인트 설명

```python
@app.post(
    "/books",
    tags=["도서"],
    summary="도서 등록",
    response_description="등록된 도서 정보",
    status_code=201,
)
def create_book(book: BookCreate):
    """
    새 도서를 등록합니다.

    - **title**: 1자 이상 100자 이하
    - **year**: 1900 이상 2100 이하
    - 같은 제목이 이미 있으면 409를 반환합니다.
    """
    ...
```

|항목|어디에 보이나|
|---|---|
|`summary`|목록에서 경로 옆에 보이는 **한 줄 제목**|
|**독스트링**|항목을 **펼쳤을 때** 나오는 상세 설명. **마크다운이 적용됨**|
|`response_description`|성공 응답 표의 `Description` 열|

> **참고:** 독스트링을 쓰는 방식이 편리합니다. `description=` 인자로도 같은 일을 할 수 있지만, 긴 설명을 데코레이터 안에 넣으면 읽기 어려워집니다.

### 2-4. 모델 필드 설명과 예시

```python
class BookCreate(BaseModel):
    title: str = Field(
        min_length=1,
        max_length=100,
        description="도서 제목",
        examples=["처음 시작하는 FastAPI"],
    )
    year: int = Field(ge=1900, le=2100, description="출판 연도", examples=[2024])
```

모델 **전체의 예시** 를 주려면 `model_config`를 씁니다. Swagger의 `Try it out`을 누를 때 이 값이 미리 채워집니다.

```python
class BookCreate(BaseModel):
    ...

    model_config = {
        "json_schema_extra": {
            "examples": [
                {
                    "title": "처음 시작하는 FastAPI",
                    "author": "빌 루바노빅",
                    "year": 2024,
                    "tags": ["python", "web"],
                }
            ]
        }
    }
```

> **참고:** 기본 예시는 `"string"`, `0` 같은 무의미한 값이라 **매번 지우고 다시 입력** 하게 됩니다.
> 실제 값을 넣어 두면 실습 속도가 눈에 띄게 빨라집니다.

### 2-5. 오류 응답 문서화

지금 문서에는 성공 응답과 `422`만 나옵니다. `404`, `409`, `502`는 **코드에 있지만 문서에 없습니다.**

```python
@app.get(
    "/books/{book_id}",
    responses={
        404: {"description": "해당 번호의 도서가 없음"},
    },
)
```

`responses`에 넣은 항목은 기존 응답을 **대체하지 않고 병합** 됩니다.

|`responses` 설정|`openapi.json`의 응답 목록|
|---|---|
|없음|`200`, `422`|
|`{404: {...}}`|`200`, **`404`**, `422`|

> **가장 중요한 개념 — 문서와 동작은 별개다**

| 구분    | 실제로 404를 **내보내는** 것             | 문서에 404를 **표시하는** 것      |
| ----- | ------------------------------- | ------------------------ |
| 담당    | `raise HTTPException(404, ...)` | `responses={404: {...}}` |
| 없으면 ? | 404가 안 나감                       | 동작은 정상, **문서에만 안 보임**    |

responses와 raise, 이 둘은 **완전히 독립적** 입니다. `responses`만 쓰고 `raise`를 안 하면
**"문서에는 404가 있는데 실제로는 안 나오는" 거짓 문서** 가 됩니다.
그리고, 이 정보가 있어야 API를 쓰는 쪽이 **어떤 상황을 처리해야 하는지** 압니다.

## 3. Postman이 필요한 이유

Swagger로 이미 테스트할 수 있는데 왜 다른 도구를 쓰는지 짚고 갑니다.

|상황|Swagger UI|Postman|
|---|---|---|
|엔드포인트 하나 빠르게 확인|**편함**|번거로움|
|요청 내용 저장해 재사용|안 됨|**됨**|
|주소를 개발·운영으로 바꿔가며 테스트|안 됨|**환경변수로 전환**|
|20개를 순서대로 한 번에 실행|안 됨|**Collection Runner**|
|응답이 맞는지 자동 검사|안 됨|**테스트 스크립트**|
|팀원과 요청 모음 공유|안 됨|**컬렉션 공유**|

정리하면 **Swagger는 만드는 중에**, **Postman은 만든 것을 반복 검증할 때** 씁니다.

오늘 코드를 고칠 때마다 20개 엔드포인트를 전부 눌러 확인하는 대신, **버튼 한 번으로 끝내는 상태** 를 만듭니다.

### 실습 2. 태그로 그룹 나누기

**목표:** 엔드포인트를 주제별로 묶는다.

**요구사항**
- 태그 4개(`시스템`, `도서`, `외부 연동`, `학습용`)를 정의하고 모든 엔드포인트에 붙인다.

**1) `main.py`에 태그 목록을 정의하고 앱에 넘깁니다.**

```python
tags_metadata = [
    {"name": "시스템", "description": "서버 상태와 앱 정보 확인"},
    {"name": "도서", "description": "내 도서 목록의 등록, 조회, 검색"},

app = FastAPI(
    title="도서 관리 API",
    description="...",
    version="1.0.0",
    contact={"name": "작성자 이름", "email": "your@email.com"},
    openapi_tags=tags_metadata,

```

**2) 각 엔드포인트에 태그를 붙입니다.**

|엔드포인트|태그|
|---|---|
|`/`, `/health`, `/info`|`시스템`|
|`/books` (GET, POST), `/books/search`, `/books/filter`, `/books/page`|`도서`|

**변경 전 → 변경 후** (인자 하나만 추가, 본문은 그대로)

```python
# 변경 전

    return {"status": "ok"}


# 변경 후

    return {"status": "ok"}
```

**확인:** `/docs`를 새로고침하면 엔드포인트가 **4개 그룹으로 접혀** 표시된다.

|확인 항목|기대 결과|
|---|---|
|그룹 개수|`시스템` / `도서` / `외부 연동` / `학습용` **4개**|
|그룹 순서|`tags_metadata`에 적은 순서 그대로|
|그룹 제목 옆|각 태그의 `description`이 함께 표시됨|
|태그를 안 붙인 엔드포인트|`default` 그룹에 남음 (누락 확인용)|

마지막 항목이 중요합니다. **`default` 그룹이 남아 있으면 태그를 빠뜨린 엔드포인트가 있다는 뜻** 입니다.

### 실습 3. 엔드포인트 설명 붙이기

**목표:** 각 엔드포인트가 무엇을 하는지 문서만 보고 알 수 있게 한다.

**요구사항**
- 주요 엔드포인트에 `summary`와 독스트링을 붙인다. 전부 할 필요는 없다.

**변경 전**

```python
@app.post("/books", response_model=BookResponse, status_code=status.HTTP_201_CREATED, tags=["도서"])
def create_book(book: BookCreate):
    for b in books:
        if b["title"] == book.title:
            raise HTTPException(status_code=409, detail="이미 등록된 제목입니다")
    new_id = max([b["id"] for b in books], default=0) + 1
    new_book = {"id": new_id, **book.model_dump()}
    books.append(new_book)
    return new_book
```

**변경 후** (데코레이터에 인자 2개 추가 + 함수 첫 줄에 독스트링. **나머지 본문은 그대로**)

```python
@app.post(
    "/books",
    response_model=BookResponse,
    status_code=status.HTTP_201_CREATED,
    tags=["도서"],
    summary="도서 등록",
    response_description="등록된 도서 정보",
)
def create_book(book: BookCreate):
    """
    새 도서를 내 목록에 등록합니다.

    - **title**: 1자 이상 100자 이하. 앞뒤 공백은 자동 제거됩니다
    - **author**: 1자 이상 50자 이하
    - **year**: 1900 이상 2100 이하
    - **tags**: 선택. 문자열 목록
    - **publisher**: 선택. 출판사 정보

    같은 제목이 이미 있으면 409를 반환합니다.
    """

        if b["title"] == book.title:
            raise HTTPException(status_code=409, detail="이미 등록된 제목입니다")
    new_id = max([b["id"] for b in books], default=0) + 1
    new_book = {"id": new_id, **book.model_dump()}
    books.append(new_book)
    return new_book
```

같은 방식으로 외부 검색에도 붙입니다.

```python
@app.get(
    "/books/external",
    response_model=list[ExternalBook],
    tags=["외부 연동"],
    summary="Google Books 검색",
    response_description="검색된 도서 목록",
)
async def search_external_books(keyword: str, limit: int = 5, fallback: bool = False):
    """
    Google Books에서 도서를 검색합니다.

    - **keyword**: 검색어. 한국어도 가능합니다
    - **limit**: 가져올 개수. 기본 5
    - **fallback**: true이면 외부 API 실패 시 예비 데이터를 반환합니다

    외부 서비스에 의존하므로 502, 504가 발생할 수 있습니다.
    """
    try:
        return await fetch_books(keyword, limit)
    except httpx.TimeoutException:
        if fallback:
            return load_fallback_books()
        raise HTTPException(status_code=504, detail="외부 API 응답이 지연됩니다")
    except httpx.HTTPStatusError:
        if fallback:
            return load_fallback_books()
        raise HTTPException(status_code=502, detail="외부 API가 오류를 반환했습니다")
    except httpx.RequestError:
        if fallback:
            return load_fallback_books()
        raise HTTPException(status_code=502, detail="외부 API에 연결할 수 없습니다")
```

> **주의:** 독스트링은 **함수 정의 바로 다음 줄** 에 와야 합니다. 그 위나 아래가 아닙니다.
> 위치가 틀리면 오류는 안 나지만 문서에 표시되지 않습니다.

**확인:**

1. `/docs`를 새로고침하고 `POST /books`를 **펼친다.**
2. 목록 줄에 경로와 함께 **"도서 등록"** 이 보인다 (`summary`).
3. 펼친 아래 설명 영역에 독스트링이 표시되고, **`-` 목록이 실제 글머리표로, `**굵게**`가 굵은 글씨로** 렌더링된다.
4. `Responses` 표의 `200`(또는 `201`) 행 `Description`에 "등록된 도서 정보"가 보인다.
5. `/redoc`에서도 같은 설명이 더 넓게 표시된다.

3번이 핵심입니다. **마크다운이 적용되지 않고 원문 그대로 보이면** 독스트링 위치가 잘못된 것입니다.

### 실습 4. 모델 예시 채우기

**목표:** `Try it out`을 눌렀을 때 쓸 만한 예시가 미리 채워지게 한다.

**요구사항**
- `schemas.py`의 `BookCreate` 각 필드에 `description`과 `examples`를 붙인다.
- 모델 전체 예시를 `model_config`로 지정한다.

**변경 전** (3일차 상태)

```python
class BookCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    author: str = Field(min_length=1, max_length=50)
    year: int = Field(ge=1900, le=2100)
    tags: list[str] = Field(default_factory=list)
    publisher: Publisher | None = None

    @field_validator("title")
    @classmethod
    def strip_title(cls, v: str) -> str:
        v = v.strip()
        if not v:
            raise ValueError("제목은 공백일 수 없습니다")
        return v
```

**변경 후** (제약 조건은 그대로 두고 설명·예시만 추가)

```python
class BookCreate(BaseModel):
    title: str = Field(
        min_length=1,
        max_length=100,
        description="도서 제목",
        examples=["처음 시작하는 FastAPI"],
    )
    author: str = Field(
        min_length=1,
        max_length=50,
        description="저자명",
        examples=["빌 루바노빅"],
    )
    year: int = Field(
        ge=1900,
        le=2100,
        description="출판 연도",
        examples=[2024],
    )
    tags: list[str] = Field(default_factory=list, description="분류 태그")
    publisher: Publisher | None = Field(default=None, description="출판사 정보")

    @field_validator("title")
    @classmethod
    def strip_title(cls, v: str) -> str:
        v = v.strip()
        if not v:
            raise ValueError("제목은 공백일 수 없습니다")
        return v

    model_config = {
        "json_schema_extra": {
            "examples": [
                {
                    "title": "처음 시작하는 FastAPI",
                    "author": "빌 루바노빅",
                    "year": 2024,
                    "tags": ["python", "backend"],
                    "publisher": {"name": "한빛미디어", "city": "서울"},
                }
            ]
        }
    }
```

> **주의:** `publisher`가 `= None`에서 `= Field(default=None, ...)`로 바뀌었습니다.
> `description`을 붙이려면 `Field`로 감싸야 하고, 이때 **기본값을 `default=`로 명시** 해야 합니다.
> 빠뜨리면 선택 필드가 필수 필드로 바뀌어 기존 요청이 `422`로 실패합니다.

**확인:**

1. 서버가 재시작된 뒤 `/docs`를 새로고침한다.
2. `POST /books`를 펼치고 `Try it out`을 누른다.
3. `Request body` 칸에 `"string"`, `0` 대신 **"처음 시작하는 FastAPI", "빌 루바노빅", 2024** 가 미리 채워져 있다.
4. **그대로 `Execute`** 를 누른다. `Code`가 `201`로 바로 등록된다.
5. 같은 화면 아래 `Schema` 탭을 누르면 각 필드 옆에 `description`이 표시된다.
6. 한 번 더 `Execute`하면 같은 제목이므로 `409`가 나온다. (정상)

`WeatherResponse`와 `ExternalBook`에도 같은 방식으로 `description`을 붙여 봅니다.

### 실습 5. 오류 응답 문서화

**목표:** 코드에는 있지만 문서에 없던 오류 상태 코드를 표시한다.

**요구사항**
- `/books/{book_id}`에 `404`, `/books`(POST)에 `409`, `/books/external`에 `502`·`504`를 문서화한다.

> **먼저 이해할 것 — 문서와 동작은 별개다**
>
> `responses`는 **문서에만 항목을 추가** 합니다. 실제 동작은 조금도 바뀌지 않습니다.
> 404를 실제로 내보내는 것은 **이미 코드에 있는 `raise HTTPException(404, ...)`** 이고,
> `responses`는 그 사실을 **문서에 알리는** 역할만 합니다.
>
> 그래서 이 실습에서는 **함수 본문을 한 글자도 고치지 않습니다.**

**변경 전**

```python
@app.get("/books/{book_id}", response_model=BookResponse, tags=["도서"])
def read_book(book_id: int):
    for book in books:
        if book["id"] == book_id:
            return book
    raise HTTPException(status_code=404, detail="도서를 찾을 수 없습니다")
```

**변경 후** (데코레이터에 `summary`와 `responses`만 추가)

```python
@app.get(
    "/books/{book_id}",
    response_model=BookResponse,
    tags=["도서"],
    summary="도서 단건 조회",
    responses={
        404: {"description": "해당 번호의 도서가 없습니다"},
    },
)
def read_book(book_id: int):
    for book in books:
        if book["id"] == book_id:
            return book
    raise HTTPException(status_code=404, detail="도서를 찾을 수 없습니다")
```

나머지 두 곳입니다. 역시 **데코레이터에 `responses`만 추가** 합니다.

```python
@app.post(
    "/books",
    response_model=BookResponse,
    status_code=status.HTTP_201_CREATED,
    tags=["도서"],
    summary="도서 등록",
    response_description="등록된 도서 정보",
    responses={
        409: {"description": "이미 등록된 제목입니다"},
    },
)
def create_book(book: BookCreate):
    ...   # 본문은 실습 3과 동일. 바꾸지 않습니다


@app.get(
    "/books/external",
    response_model=list[ExternalBook],
    tags=["외부 연동"],
    summary="Google Books 검색",
    response_description="검색된 도서 목록",
    responses={
        502: {"description": "외부 API 연결 실패 또는 오류 응답"},
        504: {"description": "외부 API 응답 지연"},
    },
)
async def search_external_books(keyword: str, limit: int = 5, fallback: bool = False):
    ...   # 본문은 실습 3과 동일. 바꾸지 않습니다
```

> **주의:** 위 두 코드 조각의 `...`은 **"기존 본문을 그대로 둔다"** 는 표시입니다.
> `...`을 그대로 복사해 붙여 넣으면 함수가 비어 버립니다.
> 전체 코드는 [6. 전체 완성 코드](#6-전체-완성-코드)에서 확인하세요.

**확인:**

1. `/docs`를 **새로고침** 하고 `GET /books/{book_id}`를 펼친다.
2. 아래 `Responses` 표의 행이 **3개** 가 되었는지 본다.

|`Code`|`Description`|출처|
|---|---|---|
|`200`|Successful Response|`response_model`에서 자동|
|**`404`**|**해당 번호의 도서가 없습니다**|**오늘 추가한 `responses`**|
|`422`|Validation Error|타입 힌트에서 자동|

3. `POST /books`에 `409`, `GET /books/external`에 `502`·`504` 행이 추가되었는지 본다.
4. `http://127.0.0.1:8000/openapi.json`을 열고 `Ctrl + F`로 **`해당 번호`** 를 검색한다. 실제 문서 파일에 들어갔는지 확인한다.

4번을 꼭 해 보세요. **화면에 보이는 것이 아니라 `openapi.json`이 실제 결과물** 이고, Postman을 비롯한 모든 도구가 이 파일을 읽어 갑니다.

#### 심화 — 오류 응답의 본문 형태까지 문서화

`description`만 주면 **응답 본문이 어떻게 생겼는지는 문서에 나오지 않습니다.** `model`을 함께 주면 스키마까지 생성됩니다.

`schemas.py`에 추가합니다.

```python
class ErrorDetail(BaseModel):
    detail: str = Field(description="오류 메시지", examples=["도서를 찾을 수 없습니다"])
```

`main.py`에서 사용합니다.

```python
from schemas import ErrorDetail

@app.get(
    "/books/{book_id}",
    response_model=BookResponse,
    tags=["도서"],
    summary="도서 단건 조회",
    responses={
        404: {"description": "해당 번호의 도서가 없습니다", "model": ErrorDetail},
    },
)
```

이러면 `404` 항목에 **예시 응답 본문** 이 함께 표시되어, API를 쓰는 쪽이 `data.detail`을 읽으면 된다는 걸 **문서만 보고** 알 수 있습니다.

### 실습 7. 환경변수 설정

**목표:** 서버 주소를 변수로 관리해 한 번에 바꿀 수 있게 한다.

주소를 요청마다 직접 적으면, 나중에 서버를 다른 곳에 올렸을 때 **20개를 전부 고쳐야 합니다.**

1. 왼쪽 사이드바에서 `Environments`를 클릭합니다.
2. `+` 버튼으로 새 환경을 만들고 이름을 `local`로 정합니다.
3. 변수를 추가합니다.

| Variable  | Initial value           | Current value           |
| --------- | ----------------------- | ----------------------- |
| `baseUrl` | `http://127.0.0.1:8000` | `http://127.0.0.1:8000` |

4. **저장** 하고, 오른쪽 위 환경 선택 드롭다운에서 `local`을 고릅니다.

**확인:** `GET /health`를 다시 `Send`한다.

|확인 항목|기대 결과|
|---|---|
|응답 상태|`200 OK` (오른쪽 위에 표시)|
|응답 본문|`{"status": "ok"}`|
|주소창에 마우스를 올리면|`{{baseUrl}}`이 실제 주소로 치환되어 표시됨|

> **참고:** 실무에서는 `local`, `dev`, `prod` 환경을 만들어 두고 **드롭다운으로 전환** 합니다.
> 같은 요청 모음을 서로 다른 서버에 그대로 실행할 수 있습니다.

#### 폴더 정리

가져온 컬렉션에서 `학습용` 폴더(`/slow-async`, `/slow-block`)는 **3초씩 걸리므로** 자동 실행에서 제외하는 게 낫습니다.
폴더 오른쪽 메뉴에서 삭제하거나, 실습 8의 실행 대상에서 빼면 됩니다.

### 실습 8. 테스트 스크립트와 일괄 실행

**목표:** 응답이 맞는지 자동으로 검사하고, 전체를 한 번에 실행한다.

|용어|의미|
|---|---|
|**테스트 스크립트**|응답을 받은 뒤 자동으로 검사하는 자바스크립트 코드|
|**`pm`**|Postman이 제공하는 객체. `pm.response`로 응답에 접근|
|**Pre-request**|요청을 **보내기 전** 에 실행되는 스크립트|
|**Post-response**|응답을 **받은 뒤** 에 실행되는 스크립트 (버전에 따라 `Tests` 탭)|
|**Collection Runner**|컬렉션 전체를 순서대로 실행하는 기능|

#### 1) `GET /health`

요청을 열고 `Scripts` 탭의 `Post-response`에 입력합니다.

```javascript
pm.test("상태 코드가 200이다", function () {
    pm.response.to.have.status(200);
});

pm.test("status 필드가 ok이다", function () {
    const data = pm.response.json();
    pm.expect(data.status).to.eql("ok");
});
```

`Send`를 누르면 응답 영역 아래 **`Test Results` 탭** 에 통과 여부가 표시됩니다.  
오른쪽 상단의 Save 버튼을 클릭해 저장합니다.

#### 2) `GET /books`

```javascript
pm.test("상태 코드가 200이다", function () {
    pm.response.to.have.status(200);
});

pm.test("배열이 반환된다", function () {
    pm.expect(pm.response.json()).to.be.an("array");
});

pm.test("응답이 2초 안에 온다", function () {
    pm.expect(pm.response.responseTime).to.be.below(2000);
});
```

#### 3) `GET /books/{book_id}` — 없는 번호 조회

주소를 `{{baseUrl}}/books/999`로 바꾸고, Post-response에 넣고 실행합니다.

```javascript
pm.test("없는 도서는 404이다", function () {
    pm.response.to.have.status(404);
});

pm.test("오류 메시지가 있다", function () {
    pm.expect(pm.response.json().detail).to.be.a("string");
});
```

#### 4) `POST /books` — 매번 다른 제목으로

같은 제목을 두 번 보내면 `409`가 나므로, 실행할 때마다 제목이 달라지게 만듭니다.

`Scripts` 탭의 **`Pre-request`** 에 넣습니다.

```javascript
pm.collectionVariables.set("randomTitle", "테스트도서_" + Date.now());
```

`Body` 탭에서 `"title"` 값을 `"{{randomTitle}}"`로 바꿉니다.

**`Post-response`** 입니다.

```javascript
pm.test("등록되면 201이다", function () {
    pm.response.to.have.status(201);
});

pm.test("id가 발급된다", function () {
    pm.expect(pm.response.json().id).to.be.a("number");
});
```

#### 5) 일괄 실행

1. 작성한 테스트 스크립트가 모두 저장되었는지 확인합니다.
2. 컬렉션 이름 오른쪽 메뉴에서 `Run collection`을 선택합니다.
3. 실행할 요청 목록에서 `학습용` 폴더의 항목 **체크를 해제** 합니다.
4. `Run`을 누릅니다.

**확인:**

1. 모든 요청이 순서대로 실행되고 상단에 **`Passed` / `Failed` 개수** 가 표시된다.
2. 작성한 테스트가 전부 통과(초록색)인지 본다.
3. **일부러 코드를 망가뜨려 본다.** `main.py`의 `/health`가 `{"status": "fine"}`을 반환하도록 바꾸고 저장한다.
4. 다시 `Run`을 누른다. **"status 필드가 ok이다" 테스트만 빨간색으로 실패** 하고 나머지는 통과한다.
5. 코드를 `"ok"`로 되돌리고 다시 실행해 전부 통과하는지 확인한다.

3~5번이 이 실습의 핵심입니다. **코드를 고친 뒤 버튼 하나로 전체가 정상인지 확인할 수 있는 상태** 가 되었습니다.

---

### 심화 (시간이 남을 때)

- `POST /books`에 잘못된 데이터를 보내 `422`가 오는지 검사하는 요청을 추가한다.
- 등록한 도서의 `id`를 변수에 저장하고, 다음 요청에서 그 번호로 조회하는 **연속 시나리오** 를 만든다.
- 컬렉션을 파일로 내보내(`Export`) 저장소에 함께 보관한다.
- `include_in_schema=False`를 붙여 `학습용` 엔드포인트를 **문서에서 숨겨** 본다.
- `deprecated=True`를 붙여 `/weather/raw`를 **사용 중단 표시** 한다.
- 응답 시간이 오래 걸리는 엔드포인트에 별도 태그를 붙여 구분한다.

## 5. 바이브코딩으로 문서화 마무리하기

여기까지 손으로 하나씩 붙여 봤습니다. **원리를 알았으니, 나머지는 AI에게 맡길 수 있습니다.**

|용어|의미|
|---|---|
|**바이브코딩 (Vibe Coding)**|AI에게 자연어로 요구사항을 주고 코드를 생성·수정하게 하는 작업 방식|

### 5-1. 왜 이 작업이 AI에 적합한가

오늘 한 작업의 성격을 보면 이유가 분명합니다.

|이 작업의 특징|AI에 적합한 이유|
|---|---|
|**기계적이고 반복적**|엔드포인트 20개에 같은 패턴을 반복 적용|
|**함수 본문을 바꾸지 않음**|로직이 망가질 위험이 낮음|
|**정답이 코드 안에 이미 있음**|`raise HTTPException(404)`를 보고 `responses`를 유추 가능|
|**틀려도 즉시 확인 가능**|`/docs`와 `openapi.json`으로 바로 검증|

반대로 **기능 로직은 AI에게 통째로 맡기기 위험합니다.** 문서화는 **가장 안전하게 AI를 써 볼 수 있는 작업** 입니다.

> **주의:** 순서가 중요합니다. **기능을 다 만든 뒤 마지막에** 문서화를 일괄 적용합니다.
> 만드는 중에 문서를 붙이면 엔드포인트가 바뀔 때마다 설명도 다시 고쳐야 합니다.

### 5-2. 좋은 프롬프트의 네 가지 요소

|요소|없으면 생기는 일|
|---|---|
|**대상 범위**|파일 전체를 제멋대로 고침|
|**하지 말 것**|함수 본문·로직까지 바꿔 버림|
|**규칙·기준**|태그 이름을 임의로 지어냄|
|**출력 형식**|설명만 늘어놓고 코드를 안 줌|

**나쁜 프롬프트와 좋은 프롬프트 대조**

|나쁜 예|왜 문제인가|
|---|---|
|"문서 좀 잘 만들어 줘"|무엇을, 어디에, 어떤 기준으로인지 없음|
|"태그 붙여 줘"|태그 이름을 AI가 지어내 실습 2와 달라짐|
|"코드 개선해 줘"|**로직까지 건드림.** 가장 위험한 프롬프트|

### 5-3. 프롬프트 예시

아래 프롬프트는 그대로 복사해 쓸 수 있습니다. AI 도구에 **해당 파일 내용을 함께 붙여 넣고** 사용하세요.

#### 예시 1. 태그 일괄 부여

```
아래는 FastAPI로 만든 main.py입니다.

각 엔드포인트 데코레이터에 tags 인자를 추가해 주세요.

태그는 아래 4개만 사용하고, 새로 만들지 마세요.
- "시스템": /, /health, /info
- "도서": /books 관련 전부 (/books/external, /books/external/multi 제외)
- "외부 연동": /weather, /weather/raw, /books/external, /books/external/multi
- "학습용": /slow-async, /slow-block

지켜야 할 것:
- 함수 본문은 한 줄도 바꾸지 마세요.
- 기존 데코레이터 인자(response_model, status_code 등)는 그대로 두세요.
- 엔드포인트 선언 순서를 바꾸지 마세요.

출력: 변경된 데코레이터 부분만 엔드포인트별로 나열해 주세요.
전체 파일을 다시 출력할 필요는 없습니다.
```

#### 예시 2. summary와 독스트링 생성

```
아래 FastAPI 엔드포인트들에 summary와 독스트링을 추가해 주세요.

작성 기준:
- summary: 한국어 명사형 한 줄. 예 "도서 등록", "도서 단건 조회"
- 독스트링: 함수 정의 바로 다음 줄에 삼중따옴표로 작성
- 독스트링 안에는 각 파라미터를 "- **이름**: 설명" 형식으로 나열
- 발생 가능한 오류 상태 코드를 마지막 줄에 한 문장으로 언급

지켜야 할 것:
- 함수 본문 로직은 바꾸지 마세요.
- 코드에 실제로 있는 파라미터와 raise HTTPException만 근거로 삼으세요.
  코드에 없는 동작을 설명에 지어내지 마세요.

출력: 엔드포인트별로 변경 후 전체 함수를 보여 주세요.
```

#### 예시 3. 오류 응답 문서화 (`responses`)

```
아래 FastAPI 코드에서 각 엔드포인트가 실제로 raise 하는 HTTPException을 찾아,
데코레이터에 responses 인자를 추가해 주세요.

규칙:
- 코드에 raise HTTPException(status_code=N, ...) 이 실제로 있는 상태 코드만 추가하세요.
- detail 문자열을 그대로 description으로 쓰세요.
- 200, 422는 자동 생성되므로 추가하지 마세요.
- 함수 본문은 바꾸지 마세요.

추가로, 각 엔드포인트마다 "코드에서 찾은 raise 위치"와
"추가한 responses 항목"을 표로 정리해 주세요.
제가 대조 검증할 수 있어야 합니다.
```

마지막 문단이 중요합니다. **AI가 근거를 함께 제시하게 만들면 거짓 문서를 걸러낼 수 있습니다.**

#### 예시 4. 모델 필드 설명과 예시

```
아래는 FastAPI 프로젝트의 schemas.py입니다.

각 Pydantic 모델 필드에 description과 examples를 추가해 주세요.

규칙:
- description은 한국어 명사형 짧은 구. 예 "도서 제목", "출판 연도"
- examples는 실제로 있을 법한 한국어 값으로. "string", "abc" 같은 무의미한 값 금지
- 기존 제약 조건(min_length, max_length, ge, le)은 그대로 유지
- 기본값이 있는 선택 필드를 Field로 감쌀 때는 default= 를 반드시 명시
  (빠뜨리면 선택 필드가 필수로 바뀝니다)
- field_validator 함수는 건드리지 마세요

BookCreate에는 model_config의 json_schema_extra로 전체 예시도 하나 추가해 주세요.
```

> **주의:** 네 번째 규칙(`default=` 명시)을 빼면 AI가 `publisher: Publisher | None = Field(description=...)`처럼 써서
> **선택 필드가 필수로 바뀌는** 사고가 자주 납니다. 프롬프트에 미리 넣어 두세요.

#### 예시 5. 누락 점검

작업을 마친 뒤 마지막으로 한 번 더 돌립니다.

```
아래 main.py와 schemas.py를 검토해 주세요.
코드를 고치지 말고, 아래 항목만 표로 정리해 주세요.

1. tags가 없는 엔드포인트
2. summary가 없는 엔드포인트
3. 독스트링이 없는 엔드포인트
4. raise HTTPException은 있는데 responses에 없는 상태 코드
5. responses에는 있는데 실제로 raise 하지 않는 상태 코드
6. description이 없는 모델 필드

5번은 특히 중요합니다. 문서에는 있는데 실제로는 발생하지 않는 오류이므로
거짓 문서가 됩니다.
```

**5번 항목이 이 프롬프트의 핵심** 입니다. 사람이 눈으로 찾기 가장 어려운 오류를 잡아 줍니다.

### 5-4. 프롬프트를 파일로 관리하기 (권장)

같은 프롬프트를 매번 다시 쓰는 것은 비효율적이고, 쓸 때마다 조금씩 달라져 결과도 달라집니다.
**규칙을 파일로 만들어 두고 그 파일을 참조하게 하는 방식** 이 더 낫습니다.

프로젝트 폴더에 `문서화-규칙.md`를 만듭니다.

```markdown
# 이 프로젝트의 API 문서화 규칙

FastAPI 프로젝트의 문서 관련 코드를 작성·수정할 때 아래 규칙을 따른다.

## 절대 지킬 것

- 함수 본문(로직)은 절대 수정하지 않는다. 데코레이터 인자와 독스트링만 추가한다.
- 엔드포인트 선언 순서를 바꾸지 않는다. 리터럴 경로가 `/books/{book_id}`보다 위에 있어야 한다.
- 코드에 실제로 존재하는 동작만 문서에 적는다. 추측해서 지어내지 않는다.

## 태그

아래 4개만 사용한다. 새 태그를 만들지 않는다.

| 태그 | 대상 |
|---|---|
| 시스템 | `/`, `/health`, `/info` |
| 도서 | `/books` 관련 (외부 연동 제외) |
| 외부 연동 | `/weather*`, `/books/external*` |
| 학습용 | `/slow-async`, `/slow-block` |

## summary

- 한국어 명사형 한 줄. 예: "도서 등록", "도서 단건 조회"
- 문장으로 쓰지 않는다. "도서를 등록합니다" (X)

## 독스트링

- 함수 정의 바로 다음 줄에 삼중따옴표로 작성한다.
- 파라미터는 `- **이름**: 설명` 형식으로 나열한다.
- 발생 가능한 오류 상태 코드를 마지막 줄에 한 문장으로 언급한다.

## responses

- 코드에 `raise HTTPException(status_code=N, ...)` 이 실제로 있는 상태 코드만 추가한다.
- `detail` 문자열을 그대로 `description`으로 쓴다.
- `200`, `422`는 자동 생성되므로 추가하지 않는다.
- 상태 코드는 정수로 쓴다. `404` (O) / `"404"` (X)

## 모델 필드

- `description`은 한국어 명사형 짧은 구. 예: "도서 제목", "출판 연도"
- `examples`는 실제로 있을 법한 한국어 값. `"string"`, `"abc"` 금지
- 기존 제약(`min_length`, `ge`, `le`)은 그대로 유지한다.
- 기본값이 있는 선택 필드를 `Field`로 감쌀 때는 `default=`를 반드시 명시한다.
  빠뜨리면 선택 필드가 필수로 바뀐다.
- `field_validator` 함수는 건드리지 않는다.

## 작업 후 보고

변경한 내용을 아래 표로 정리해 제출한다.

| 엔드포인트 | 추가한 항목 | 근거 (코드의 어느 줄) |
|---|---|---|
```

이렇게 만들어 두면 프롬프트가 한 줄로 줄어듭니다.

```
문서화-규칙.md 의 규칙에 따라 main.py의 모든 엔드포인트에 tags와 summary를 추가해 주세요.
```

|파일로 관리할 때의 이점|
|---|
|매번 같은 결과가 나온다 (일관성)|
|규칙을 고치면 이후 모든 작업에 반영된다|
|팀원·조원이 같은 규칙을 공유한다|
|저장소에 함께 커밋되어 기록으로 남는다|
|"왜 이렇게 썼는지"가 문서로 남는다|

### 5-5. 그 밖의 방법

상황에 따라 아래 방식이 더 편할 수 있습니다.

|방법|어떻게|언제 유용한가|
|---|---|---|
|**규칙 파일 참조**|`문서화-규칙.md`를 만들고 프롬프트에서 참조|**반복 작업, 팀 공유** (5-4)|
|**상시 규칙 파일**|AI 도구가 자동으로 읽는 파일에 규칙을 둠|매번 지시하기 귀찮을 때|
|**예시 기반 (few-shot)**|잘 된 엔드포인트 하나를 보여주고 "이 스타일로 나머지도"|규칙을 말로 설명하기 어려울 때|
|**단계 분할**|파일 단위·태그 그룹 단위로 나눠 요청|한 번에 시켜 결과가 엉킬 때|
|**검토 전용 요청**|"고치지 말고 문제점만 표로" (5-3 예시 5)|**AI 결과를 믿기 전에**|

#### 상시 규칙 파일

AI 코딩 도구는 프로젝트 폴더의 특정 파일을 **매번 자동으로 읽습니다.** 도구마다 파일 이름이 다릅니다.

|도구|파일 위치|
|---|---|
|Claude Code|프로젝트 루트의 `CLAUDE.md`|
|Cursor|`.cursorrules` 또는 `.cursor/rules/`|
|GitHub Copilot|`.github/copilot-instructions.md`|

여기에 5-4의 규칙을 넣어 두면 **프롬프트에 규칙을 언급하지 않아도** 적용됩니다.

> **주의:** 상시 규칙은 편하지만 **적용됐는지 눈에 보이지 않습니다.**
> 결과가 규칙과 다르면 파일을 제대로 읽었는지부터 확인하세요. 학습 단계에서는 5-4의 명시적 참조 방식이 더 안전합니다.

#### 예시 기반 요청

규칙을 글로 쓰기 어려울 때는 **완성된 예시 하나** 를 보여주는 편이 빠릅니다.

```
아래는 제가 직접 작성한 엔드포인트입니다. 이것이 기준 스타일입니다.

[여기에 실습 3에서 완성한 POST /books 전체 코드를 붙여넣기]

같은 스타일로 아래 엔드포인트들에도 summary와 독스트링을 붙여 주세요.
- summary 길이, 독스트링 형식, 파라미터 나열 방식을 위 예시와 똑같이 맞춰 주세요.
- 함수 본문은 바꾸지 마세요.

[대상 엔드포인트 코드 붙여넣기]
```

#### 단계 분할

엔드포인트 20개에 네 가지 작업(태그·summary·독스트링·responses)을 **한 번에** 시키면 결과가 길어져 누락이 생기고, 어디가 틀렸는지 찾기도 어렵습니다.

|나쁜 순서|좋은 순서|
|---|---|
|"문서화 전부 해 줘" 한 번|① 태그만 → 확인 → ② summary만 → 확인 → ③ 독스트링 → 확인 → ④ responses → 확인|

**각 단계마다 서버를 재시작하고 `/docs`를 확인** 하면, 문제가 생겼을 때 원인이 직전 단계로 좁혀집니다.

### 5-6. 반드시 직접 검증하기

AI가 만든 문서는 **그럴듯하지만 틀릴 수 있습니다.** 아래를 직접 확인하세요.

- [ ] 서버가 오류 없이 재시작된다 (문법 오류 없음)
- [ ] `/docs`에서 태그 그룹이 **4개** 이고 `default` 그룹이 **없다**
- [ ] `responses`에 적힌 상태 코드가 **코드에 실제로 `raise` 되어 있다**
- [ ] 독스트링의 파라미터 목록이 **실제 함수 시그니처와 일치** 한다
- [ ] 선택 필드가 여전히 선택이다 (`POST /books`를 `tags` 없이 보내 `201`이 나오는지)
- [ ] 실습 8의 Postman Collection Runner가 **전부 통과** 한다

마지막 항목이 가장 강력합니다. **오늘 만든 테스트가 AI 작업의 안전망이 됩니다.**
문서화 전에 Postman 테스트를 먼저 만들어 두면, AI가 무엇을 망가뜨렸는지 즉시 알 수 있습니다.

> **참고:** 이것이 오늘 실습 순서의 이유이기도 합니다.
> 실무에서도 **테스트를 먼저 갖춘 뒤 AI에게 대규모 수정을 맡기는** 것이 안전합니다.

from pydantic import BaseModel, Field, field_validator


class Publisher(BaseModel):
    name: str = Field(description="출판사 이름", examples=["한빛미디어"])
    city: str = Field(default="서울", description="출판사 소재 도시")


class BookCreate(BaseModel):
    title: str = Field(
        min_length=1,
        max_length=100,
        description="도서 제목",
        examples=["처음 시작하는 FastAPI"],
    )
    author: str = Field(
        min_length=1,
        max_length=50,
        description="저자명",
        examples=["빌 루바노빅"],
    )
    year: int = Field(
        ge=1900,
        le=2100,
        description="출판 연도",
        examples=[2024],
    )
    tags: list[str] = Field(default_factory=list, description="분류 태그")
    publisher: Publisher | None = Field(default=None, description="출판사 정보")

    @field_validator("title")
    @classmethod
    def strip_title(cls, v: str) -> str:
        v = v.strip()
        if not v:
            raise ValueError("제목은 공백일 수 없습니다")
        return v

    model_config = {
        "json_schema_extra": {
            "examples": [
                {
                    "title": "처음 시작하는 FastAPI",
                    "author": "빌 루바노빅",
                    "year": 2024,
                    "tags": ["python", "backend"],
                    "publisher": {"name": "한빛미디어", "city": "서울"},
                }
            ]
        }
    }


class BookResponse(BookCreate):
    id: int = Field(description="서버가 발급한 도서 번호", examples=[1])


class WeatherResponse(BaseModel):
    latitude: float = Field(description="위도", examples=[36.8])
    longitude: float = Field(description="경도", examples=[127.1])
    temperature: float = Field(description="현재 기온(섭씨)", examples=[28.9])
    time: str = Field(description="관측 시각", examples=["2026-08-04T09:00"])


class ExternalBook(BaseModel):
    title: str = Field(description="도서 제목", examples=["처음 시작하는 FastAPI"])
    authors: list[str] = Field(default_factory=list, description="저자 목록")
    published_date: str = Field(default="", description="발행일. 없을 수 있음")


class ErrorDetail(BaseModel):
    detail: str = Field(description="오류 메시지", examples=["도서를 찾을 수 없습니다"])
```

def create_from_external(book: ExternalBook):
    """
    Google Books 검색 결과를 내 도서 목록에 등록합니다.

    - **title**: 도서 제목
    - **authors**: 저자 목록. 첫 번째 저자만 사용하며, 비어 있으면 "미상"이 됩니다

    new_book = {
        "id": new_id,
        "title": book.title,
        "author": book.authors[0] if book.authors else "미상",
        "year": year,
        "tags": ["외부검색"],

    도서 번호로 한 건을 조회합니다.

    - **book_id**: 조회할 도서 번호

    해당 번호의 도서가 없으면 404를 반환합니다.
    """
    for book in books:
        if book["id"] == book_id:
            return book
    raise HTTPException(status_code=404, detail="도서를 찾을 수 없습니다")
```

### 웹 실습 2. API 상태 점검 대시보드

파일: `static/19-dashboard.html` — 주요 엔드포인트를 한 번에 호출해 상태 코드와 응답 시간을 표로 보여줍니다.
**Postman Collection Runner의 축소판** 입니다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>API 상태 점검</title>
  <style>
    table { border-collapse: collapse; }
    th, td { border: 1px solid #ccc; padding: 6px 12px; text-align: left; }
    .ok { color: green; }
    .fail { color: red; }
  </style>
</head>
<body>
  <h1>API 상태 점검</h1>
  <button id="runBtn">전체 점검</button>
  <p id="summary"></p>

  <table>
    <thead>
      <tr><th>엔드포인트</th><th>기대</th><th>결과</th><th>시간(ms)</th></tr>
    </thead>
    <tbody id="rows"></tbody>
  </table>

  <script>
    const checks = [
      { path: "/health", expect: 200 },
      { path: "/info", expect: 200 },
      { path: "/books", expect: 200 },
      { path: "/books/1", expect: 200 },
      { path: "/books/9999", expect: 404 },
      { path: "/books/search?keyword=python", expect: 200 },
      { path: "/books/page?skip=0&limit=2", expect: 200 },
      { path: "/weather", expect: 200 },
      { path: "/books/external?keyword=fastapi", expect: 200 }
    ];

    document.getElementById("runBtn").addEventListener("click", async () => {
      const rows = document.getElementById("rows");
      const summary = document.getElementById("summary");
      rows.innerHTML = "";
      summary.textContent = "점검 중...";

      let pass = 0;

      for (const check of checks) {
        const start = performance.now();
        let status = "실패";
        try {
          const res = await fetch(check.path, { cache: "no-store" });
          status = res.status;
        } catch (e) {
          status = "연결 실패";
        }
        const elapsed = Math.round(performance.now() - start);
        const isOk = status === check.expect;
        if (isOk) pass++;

        const tr = document.createElement("tr");
        tr.innerHTML =
          "<td>" + check.path + "</td>" +
          "<td>" + check.expect + "</td>" +
          "<td class='" + (isOk ? "ok" : "fail") + "'>" + status + "</td>" +
          "<td>" + elapsed + "</td>";
        rows.appendChild(tr);
      }

      summary.textContent = "통과 " + pass + " / " + checks.length;
    });
  </script>
</body>
</html>
```

## 9. 오늘의 정리

- FastAPI는 코드에서 **OpenAPI 문서** 를 자동 생성한다. `/docs`, `/redoc`, `/openapi.json`은 같은 내용을 다르게 보여준다.
- 자동 생성만으로는 부족하다. `title`, `tags`, `summary`, 독스트링, `description`, `examples`, `responses`로 다듬는다.
- **`responses`는 문서만 바꾼다.** 실제 오류는 `raise HTTPException`이 낸다. 둘이 어긋나면 거짓 문서가 된다.
- 문서를 다듬으면 Swagger 화면만 좋아지는 것이 아니다. **OpenAPI를 읽는 모든 도구** 가 그 정보를 함께 가져간다.
- Swagger는 **만드는 중에**, Postman은 **만든 것을 반복 검증할 때** 쓴다.
- Postman의 환경변수로 서버 주소를 분리하면 같은 요청 모음을 여러 환경에 실행할 수 있다.
- 테스트 스크립트와 Collection Runner로 전체 검증을 자동화한다. 코드를 고친 뒤 버튼 한 번으로 확인한다.
- 문서화는 기계적인 작업이라 **AI에게 맡기기 좋다.** 단, 테스트를 먼저 갖추고 결과를 직접 검증한다.

5일차에는 수정·삭제를 추가해 **CRUD를 완성** 하고, 지금까지의 코드를 **정리·리뷰** 합니다.

## 10. 자주 나는 오류와 해결

### 문서화 관련

|증상 / 오류 메시지|원인|해결|
|---|---|---|
|`/docs`에 변경이 반영 안 됨|브라우저 캐시|`Ctrl + F5`로 강제 새로고침|
|`default` 그룹이 남아 있음|`tags`를 빠뜨린 엔드포인트가 있음|`default` 그룹을 펼쳐 어떤 것인지 확인|
|태그 그룹 순서가 이상함|`openapi_tags`에 없는 태그 이름을 씀|`tags_metadata`의 `name`과 철자를 맞춤|
|독스트링이 문서에 안 보임|위치가 함수 첫 줄이 아님|`def` 바로 다음 줄로 이동|
|독스트링이 원문 그대로 보임|마크다운 문법 오류 (`-` 뒤 공백 없음 등)|`- **이름**: 설명` 형식 확인|
|`Try it out` 예시가 그대로 `"string"`|`model_config` 위치가 클래스 밖|클래스 **안쪽** 들여쓰기 확인|
|기존 요청이 갑자기 `422`|선택 필드를 `Field`로 감싸며 `default=`를 빠뜨림|`Field(default=None, ...)`로 수정|
|`responses`에 넣었는데 안 보임|상태 코드를 문자열로 씀 (`"404"`)|정수 `404`로 작성|
|문서엔 있는데 실제로 그 오류가 안 남|`responses`만 쓰고 `raise`가 없음|코드에 `raise HTTPException` 있는지 확인|

### Postman 관련

|증상 / 오류 메시지|원인|해결|
|---|---|---|
|`Could not send request`|`{{baseUrl}}`이 비어 있음|`Environments`에서 `local` 생성 후 **드롭다운에서 선택**|
|로컬 주소에 연결 안 됨|**웹 버전** 을 쓰고 있음|데스크톱 앱 설치|
|`ECONNREFUSED`|서버가 꺼져 있음|`fastapi dev main.py` 실행 확인|
|`Import` 후 폴더가 하나뿐|실습 2의 태그를 안 붙인 상태로 가져옴|태그 적용 후 `openapi.json`을 다시 Import|
|`Scripts` 탭이 안 보임|Postman 버전 차이|`Tests` 탭을 찾아 사용|
|`POST /books`가 계속 `409`|같은 제목을 반복 전송|`Pre-request`의 `randomTitle` 설정 확인|
|테스트가 전부 실패|환경 선택이 해제됨|오른쪽 위 드롭다운에서 `local` 재선택|
|`Run collection`이 오래 걸림|`학습용` 폴더가 포함됨 (3초씩)|실행 목록에서 체크 해제|

### 문제가 안 풀릴 때

1. 문서 문제는 **`openapi.json`을 직접 열어** 확인합니다. 화면이 아니라 이 파일이 실제 결과물입니다.
2. 서버가 안 뜨면 터미널의 traceback 마지막 줄을 봅니다. 대부분 데코레이터 괄호나 쉼표 문제입니다.
3. 기능이 망가졌으면 `19-dashboard.html`이나 Postman `Run collection`으로 **어디가 깨졌는지** 좁힙니다.
4. 그래도 안 되면 [6. 전체 완성 코드](#6-전체-완성-코드)와 본인 코드를 파일별로 비교합니다.

### 1~3일차 용어 복습

|용어|한 줄 정의|
|---|---|
|**`response_model`**|응답 형태를 고정·검사하는 옵션. 값을 생성하지는 않음|
|**`HTTPException`**|상태 코드와 함께 오류 응답을 내보내는 예외. `return`이 아니라 `raise`|
